マイクラサーバーが重い・ラグの原因と対処法

TPS低下・ラグを計測し、原因に合った対処を一つずつ試すためのガイドです。

想定読了: 8分 対象: Java版 Paper / Vanilla 目的: TPS改善・ラグ解消
※この記事には広告・PRリンクを含みます。

先に結論（計測してから対処）

  1. TPS・処理時間・回線状況を確認して、サーバー負荷と通信・クライアント側の問題を切り分ける
  2. チャンク関連の負荷が高ければ、view-distance / simulation-distanceを下げて比較する
  3. RAM割り当てとGCを確認する。メモリを増やすだけで改善するとは限らない
  4. sparkで重い処理を調べる。疑わしいプラグインはバックアップを取り、停止中に一つずつ見直す
  5. 追加GCフラグは必要な場合に検証する。現代のJVMでは、まず既定のGC設定で計測する

症状別 原因の候補

症状だけでは原因を断定できません。ラグが起きている時間の計測結果やログと照合してください。

症状考えられる原因優先確認箇所
全員が同時にラグるサーバー負荷・サーバー側回線の混雑などTPS / CPU / メモリ / 通信状況
特定のプレイヤーだけラグるそのプレイヤーの回線・端末描画負荷など遅延・パケットロス・FPS
特定のエリアに入ると重くなる大量エンティティ・チャンク生成・描画負荷などsparkの計測結果・エンティティ数・FPS
定期的に一瞬フリーズするGC・保存処理・ディスクI/OなどGCログ・spark・保存時刻
夜間だけ重くなるバックアップ・自動タスク・回線混雑など実行スケジュール・通信状況

TPS の確認方法（Paper）

Paperでは、権限のあるプレイヤーがゲーム内で /tps を実行すると、直近1・5・15分のTPSを確認できます。Vanilla標準にはこのコマンドはありません。コンソールでは先頭の / を省きます。

/tps

出力例: TPS from last 1m, 5m, 15m: 19.98, 19.54, 18.31

通常の目標は20 TPSです。低下が続く場合はサーバーの処理遅延が疑われますが、平均TPSだけでは短い停止や通信遅延を判断できません。Paper公式は詳しい性能確認にsparkを案内しています（Paperのコマンド一覧）。

対処1: 描画距離・シミュレーション距離を見直す

サーバーを停止して設定ファイルをバックアップし、server.properties の既存行を編集します。以下は比較用の例で、万能な推奨値ではありません。

view-distance=8
simulation-distance=6

両方の既定値は 10 です。view-distance はクライアントへ送るワールドの範囲、simulation-distance はエンティティを更新する範囲に関係します。下げると負荷が減る場合がありますが、見える範囲や離れた場所のモブ・装置の動作に影響します。一度に一項目を変更し、再起動して同じ条件で比較してください。Paper/Spigotのワールド別設定による上書きにも注意してください（server.properties公式リファレンス）。

対処2: メモリ・GCを確認して起動設定を見直す

Paperの公式起動スクリプトジェネレーターは、Java 17・21以降の現代のJVMでは、まず追加GCフラグなしの既定設定を試すよう案内しています。使用するサーバーバージョンに対応したJavaで計測し、GCが問題の場合や古い環境で必要な場合に、Aikarフラグの公式説明を確認して比較してください。すべてのラグが改善する設定ではありません。

手動起動の例です。server.jar があるフォルダで実行する一行のコマンドで、Windowsの start.bat にも記述できます。java が利用可能であることを確認してください。

java -Xms4G -Xmx4G -jar server.jar --nogui

4G は例です。Xms は初期ヒープ、Xmx は最大ヒープで、Javaプロセス全体のメモリ上限ではありません。OS・同時起動するゲーム・ヒープ外メモリの余裕を残してください。MaiPilotから起動する場合は、アプリの設定を変更し、別のスクリプトから同じサーバーを重複起動しないでください。

対処3: sparkで重い処理を調べる

Paper 1.21以降にはsparkが同梱されています。旧バージョンのPaperでは、spark公式の導入手順に従い、使用中のサーバー・Javaに対応するプラグインを導入してください。VanillaにはPaper用プラグインをそのまま追加できません。

  1. ラグが発生している状態で、権限のあるプレイヤーがゲーム内で次のコマンドを実行する。コンソールでは先頭の / を省く。
  2. 問題が再現する通常のプレイを続けて計測する。
  3. 10分後に出力されるレポートURLを開き、時間を使っている処理を確認する。
  4. プラグインが疑われる場合はバックアップを取り、サーバー停止中に依存関係も確認して一つずつ設定変更・無効化する。再起動後、同じ条件で再計測する。
/spark profiler start --timeout 600

Timingsは非推奨で、Paper 1.21では既定で無効です。新たな診断にはsparkを使ってください。レポートを他人へ共有する前には内容を確認してください（Paper公式のプロファイリング手順）。

対処4: エンティティの負荷を見直す

大量のモブやドロップアイテムが原因と分かった場合は、装置や飼育数、アイテム回収を見直します。server.properties に max-entities という標準設定はありません。

Paper/Spigotのスポーン上限は bukkit.yml の spawn-limits などで管理され、Paperではワールド設定で上書きされる場合があります。spigot.yml の entity-activation-range はエンティティの動作範囲の設定で、総数の上限ではありません。設定場所・階層・対応バージョンは、bukkit.ymlとspigot.ymlの公式リファレンスで確認し、バックアップ後に編集してください。

Paperでは、権限のあるプレイヤーが次のコマンドで現在のワールドのエンティティ数を種類別に確認できます。これだけで重いチャンクや原因を断定せず、sparkの結果と合わせて調べてください（コマンドの説明）。

/paper entity list

よくある質問

TPSとは何ですか？どうやって確認しますか？
TPSは1秒あたりのサーバーの処理回数で、通常の目標は20です。Paperでは権限があれば /tps で確認できますが、Vanilla標準のコマンドではありません。低下は処理遅延の目安で、通信遅延や短い停止はTPSだけでは判断できません。詳しい調査にはsparkを使います。
Aikarフラグとは何ですか？
Minecraftサーバー向けにGCの動作を調整するJVM起動オプション群です。Paper公式は、Java 17・21以降の現代のJVMではまず追加GCフラグなしを試し、GCの問題がある場合や古い環境で検討するよう案内しています。効果は計測して判断してください。
view-distanceを下げるとどんな影響がありますか？
クライアントへ送るワールドの範囲が狭くなり、負荷を減らせる場合があります。simulation-distanceはエンティティを更新する範囲に関係します。見える景色や離れたモブ・装置の動作に影響するため、一項目ずつ変更し、再起動後に比較してください。
プラグインがラグの原因か調べるには？
Paper 1.21以降は同梱のsparkで、ラグ発生中に /spark profiler start --timeout 600 を実行し、10分後のレポートを確認します。旧Paperでは公式手順で対応するsparkを導入してください。疑わしいプラグインはバックアップ後、停止中に一つずつ見直し、再起動して比較します。
