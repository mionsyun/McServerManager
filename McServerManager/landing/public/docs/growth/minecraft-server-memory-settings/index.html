マイクラサーバーのメモリ設定（Xms/Xmx目安）

Java版サーバーのメモリは、人数だけでは決まりません。使うバージョンと構成の要件を確認し、普段の遊び方で測って調整しましょう。

先に結論

  • Xms はJavaヒープの初期サイズ、Xmx は最大サイズです。PC全体やJavaプロセス全体の使用量ではありません。
  • サーバーソフト・Minecraft・MODパックの対応バージョンと推奨要件を出発点にします。人数だけから必要量は保証できません。
  • OS、同時に遊ぶMinecraftクライアント、他のアプリ、Javaのヒープ外メモリにも余裕を残してください。
  • 統合版のBedrock Dedicated Server（BDS）はJavaを使わないため、Xms/Xmxは適用されません。

Xms / Xmxと実際のメモリ使用量

-Xms2048M -Xmx4096M は、初期ヒープ2GiB・最大ヒープ4GiBの指定例です。これは全構成への推奨値ではありません。Javaはヒープ以外にもクラス情報、スレッド、ネイティブバッファなどのメモリを使うため、XmxをPCの搭載量いっぱいに設定しないでください。

XmsはXmx以下にします。同値を前提とする起動設定もありますが、すべての構成に一律の比率を当てはめる必要はありません。サーバーやMODパックの説明に従い、同じPCでゲームも動かす場合は起動時の余裕も確認します。

MaiPilotのJavaサーバーではXms/XmxをMB単位で設定できます。概要のメモリ表示はプロセスのワーキングセットに基づく値で、Javaヒープ使用量やGCの計測値ではありません。表示だけでヒープ不足と断定しないでください。

設定を見直す手順

  1. サーバーを停止し、現在の設定を控えます。使用中のサーバー・MODパックが指定するJava版、メモリ要件を確認します。
  2. OSと普段同時に使うアプリの使用量を確認し、Javaのヒープ外も含めた余裕を残してXmxを決めます。必要な余裕はPCごとに異なります。
  3. 同じ人数・場所・操作で、TPSや処理時間、CPU負荷、OSの空きメモリ、ログを記録します。Paperでは対応するプロファイラでGCや処理負荷も調べられます。
  4. ヒープ不足が確認でき、PC側にも余裕がある場合に割り当てを見直します。CPU負荷、チャンク生成、回線などが原因なら、増量だけでは解決しません。
  5. 一度に一つの設定だけ変更し、再起動後に同じ条件で比較します。改善しない場合は元に戻し、ラグ対策ガイドで別の原因を確認します。

よくある質問

Xmxを大きくすると必ず速くなりますか？
必ず速くなるわけではありません。ヒープ不足以外の原因には効かず、OSや他のアプリのメモリを圧迫すると悪化することがあります。
XmsはXmxと同じ値にすべきですか？
サーバーやMODパックの起動手順に従ってください。同値を前提とする設定もありますが、一律の比率はありません。XmsはXmx以下にし、PC全体の余裕と実測結果で判断します。
どれくらいの頻度で見直すべきですか？
プレイヤー数やMOD/プラグインを増やしたタイミングで見直すのが効果的です。
